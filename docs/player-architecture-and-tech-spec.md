# zakoway 视频播放系统架构与设计选型规范
> 本文档基于对 **animaku (Web)**、**Kazumi (Flutter)**、**AniBaka (Flutter)** 三大项目的源码深度调研，为 **zakoway (Flutter)** 制定工业级、跨平台的动漫播放系统落地规范与技术路线图。

---

## 1. 架构目标与设计哲学

zakoway 作为 animaku 的移动与多端增强版本，播放模块需同时满足：
1. **极致播放性能与跨平台稳定性**：适配 Android、iOS、Windows、macOS、Linux，支持硬解与自适应渲染。
2. **继承 animaku 最强业务大脑**：直接移植经过实战验证的**多源并发探测、智能仲裁、自动故障转移算法**。
3. **吸收 Kazumi 的多端工程化体验**：全屏/宽屏下的**悬浮侧边抽屉（SidePanel）**，选集与换源无需打断播放。
4. **借鉴 AniBaka 的极客级视听与微交互**：**Anime4K GLSL 动漫超分**、**自研 Canvas 弹幕引擎**、**彩色 OP/ED 进度条刻度**与**细腻手势系统**。
5. **高频渲染与低频控制彻底解耦**：毫秒级时间线刷新与重型 UI 控制层物理隔离，杜绝掉帧。

---

## 2. 核心技术选型与底座

### 2.1 底层播放内核
* **选型**：`media_kit` + `media_kit_video` + `media_kit_libs_video` (基于 **libmpv**)
* **选型理由**：
  * Flutter 生态中唯一能够覆盖移动端与桌面端的工业级视频播放器；
  * 原生支持自定义 HTTP 请求头（`Referer`、`User-Agent`，动漫源防盗链必备）；
  * 原生支持 HLS/m3u8 及其解析、多音轨、内嵌字幕及外挂 ASS/SRT 字幕；
  * 底层 mpv 支持直接挂载原生 **GLSL 视频着色器**（为 Anime4K 铺平道路）；
  * 支持平台硬件解码加速配置（D3D11VA, NVDEC, VAAPI, VideoToolbox, MediaCodec）。

### 2.2 状态管理与时间线解耦
* **架构设计**：
  * 禁止将 `position` / `duration` 高频状态直接塞入全局 Riverpod / StateNotifier 引起整个播放页或控件树重绘；
  * 采用 **两层状态模型**（类似 animaku 的 `timeStore` 与 AniBaka 的细粒度 `ValueNotifier`）：
    1. **低频控制状态（Core & Overlay State）**：播放/暂停、缓冲中、控制栏显隐、全屏、倍速、侧边栏展开等；
    2. **高频时间线状态（Timeline State）**：以 250ms 节流派发时间戳，仅供进度条、时间文本和弹幕时间轴局部监听；配合 `RepaintBoundary` 对视频渲染图层、弹幕图层、控制图层进行物理隔离。

## 3. 六大核心子系统设计

### 3.1 子系统一：多源并发测速与自适应仲裁（源自 animaku）

直接继承 animaku 经过千万次播放检验的 `use-auto-source-pick` 逻辑：

```
[用户触发番剧/某集播放]
        │
        ├─ 并发发起所有可用视频源的检索/探测 (In-Flight Plugins)
        │
        ▼
[候选源状态机仲裁 (resolveAutoSourceDecision)]
        ├─ 无候选就绪 ───────────────> 等待检索结果
        │
        ├─ 最优源(优先级最高)已就绪 ──> [Immediate 0ms 秒提] 立即起播
        │
        └─ 次优源已就绪，但更高优先级源在途中
                │
                ▼
        [Wait Grace 宽限窗口 (默认 1200ms)]
                ├─ 窗口期内高优先级源就绪 ──> 立即切换并起播最高优源
                └─ 窗口超时仍未就绪 ───────> 降级起播次优源
```

* **自动故障转移（Auto-Fallback）**：播放中遇到网络超时、403 防盗链拦截或流解码失败时，静默拉取下一候选源重试，无需用户手动回退。
* **源看板（SourceBoard）**：保留可视化的视频源切换面板，展示延迟、有效线路与源状态。

---

### 3.2 子系统二：多端自适应布局与全屏悬浮抽屉（源自 Kazumi + animaku）

#### 1. 桌面端 / 全屏模式：悬浮抽屉式交互（`VideoSidePanel`）
* **痛点解决**：全屏看剧时，选集或切源不再弹出大弹窗遮挡画面，也不再强制退出全屏；
* **交互细节**：
  * 悬浮在画面右侧（半透明毛玻璃背景）；
  * 包含「选集列表」、「多线路切换」、「Bangumi 章节吐槽评论区」三个 Tab；
  * 抽屉打开时，视频画面在左侧持续流畅播放；
  * 自动滚动并高亮当前正播剧集（`revealCurrentEpisode`）。

#### 2. 移动端竖屏模式：
* 顶部保持 16:9 播放区域（支持页面滚动吸顶或一键转为 PiP 画中画）；
* 下方提供 TabView 联动：
  * **选集**：网格视图与横滑卡片视图一键切换；
  * **简介**：番剧信息、演职员、放送时间、关联番剧；
  * **评论**：吐槽与讨论；
  * **视频源**：查看与手动固定切换各聚合源。

---

### 3.3 子系统三：Anime4K 动漫超分辨率画质增强（源自 AniBaka）

在 Flutter 端通过 mpv 原生着色器管道无缝实现 Anime4K v4：

* **实现原理**：
  * 将 Anime4K v4 的精选 GLSL 算法文件内置到 app assets（Clamp, Restore CNN, Upscale CNN, AutoDownscalePre 等）；
  * 启动时动态释放到 App 本地缓存目录；
  * 通过 `media_kit` 的底层 mpv 属性调用 `_setNativeProperty('glsl-shaders', paths)`，完全由底层 GPU 硬件管线接管渲染，不消耗 Flutter 渲染树性能。
* **分级预设模型**：
  * **关闭 (Off)**：原画输出，超低功耗；
  * **低 (Low / 移动推荐)**：Clamp + Restore_M + Upscale_S，低发热，明显消除噪点与压缩块；
  * **中 (Medium)**：Clamp + Restore_M + Upscale_M，线条清晰锐利；
  * **高 (High / 桌面推荐)**：针对大屏显示器深度还原画质；
  * **极限 (Ultra)**：多级 CNN 迭代超分。

### 3.4 子系统四：自研高性能 Canvas 弹幕引擎（源自 AniBaka + animaku）

抛弃重型第三方弹幕库，基于 Flutter 原生 `CustomPainter` + `Ticker` 架构实现：

* **防重叠智能轨道分配算法**：
  * 根据当前字号动态划分屏幕垂直轨道（`_scrollTracks`）；
  * 滚动弹幕逐轨道排查，若当前轨道最后一颗弹幕的尾部尚未离开屏幕安全间距，自动寻找下一轨道；
  * 顶部/底部固定弹幕维护独立的占用时间窗口（`_topBusyUntil` / `_bottomBusyUntil`）。
* **10秒防刷屏去重窗口（`_repeatWindowMs = 10000`）**：
  * 追番高峰期，同屏常出现大量相同复读弹幕；
  * 引擎在 10s 滑动窗口内对相同文本进行合并/压制，防止大面积遮挡。
* **节电与低功耗控制**：
  * 当前无活动弹幕且视频暂停时，自动暂停 Ticker 调度，防止无意义唤醒 GPU。
* **交互与过滤能力**：
  * 快捷三段式开关：**全部显示 $\rightarrow$ 精简模式 $\rightarrow$ 全部关闭**；
  * 弹幕设置面板：透明度、字号缩放、飞行速度、轨道区域（顶/底/半屏/全屏）、描边样式、屏蔽词规则（支持正则）。

---

### 3.5 子系统五：OP/ED 彩色进度条与自动跳过（源自 AniBaka + animaku）

* **彩色进度条刻度（`SkipSegmentTrack`）**：
  * 利用 `CustomPainter` 在进度条轨道下方/内部绘制高亮色彩段：
    * **薄荷青色 (`#65D1C5`)**：OP 片头区间；
    * **暖淡橙色 (`#F2BA72`)**：ED 片尾区间；
  * 直观提示正片位置，拖动进度一目了然。
* **数据来源与手动纠偏**：
  * 优先使用 Bangumi API 的片头片尾时间标注；
  * 提供「OP/ED 标记器」支持用户自定义或手动修正并本地记忆。
* **跳过与防误触**：
  * 自动跳过触发时，弹出带「撤销跳过」操作的微型 HUD Toast，误判时可一键回到跳过前位置。

---

### 3.6 子系统六：全功能手势系统与按键映射（源自 AniBaka + Kazumi）

#### 1. 移动端手势体系
* **三等分双击**：
  * 屏幕左 1/3：双击快退（可连续点击累加步长：-10s $\rightarrow$ -20s $\rightarrow$ -30s）；
  * 屏幕中 1/3：双击暂停 / 播放；
  * 屏幕右 1/3：双击快进（累加 +10s $\rightarrow$ +20s）；
* **长按动态无级变速**：
  * 长按进入 2x 快速播放；
  * 长按期间手指**水平左右滑动**，可在 1.0x ~ 5.0x 之间无级动态调整倍速，松手立即恢复原速；
* **左亮度、右音量垂直滑动**：
  * 左半屏上下滑动调节屏幕亮度；
  * 右半屏上下滑动调节播放器音量；
  * 配合平滑缓动动画的 HUD 浮标指示器。
* **Seek Preview 拖拽预览**：
  * 水平拖动时只刷新 HUD 预览时间，不触发底层卡顿的视频 seek；松手后一次性精准跳转。
* **误触锁定按钮**：一键锁定屏幕手势。

#### 2. 桌面端键盘快捷键系统
* `Space`：播放 / 暂停
* `←` / `→`：快退 5s / 快进 5s（长按连续快进）
* `↑` / `↓`：音量 +10% / -10%
* `F`：切换全屏（或双击画面全屏）
* `M`：静音 / 取消静音
* `[` / `]`：上一集 / 下一集
* `D`：切换弹幕（全开/精简/关）
* `C`：画面截图（可配置是否包含弹幕，并保存至相册/剪贴板）

## 4. 分期实施路线图 (Roadmap)

### 阶段一：播放器底座与基础播放架构 (Foundation)
- [ ] 引入 `media_kit`、`media_kit_video` 相关依赖，配置各平台原生构建参数；
- [ ] 封装 `PlaybackController`，实现基础的播放、暂停、Seek、音量、倍速控制；
- [ ] 构建双层状态系统：将高频时间线 `TimelineState` 与 UI 控制 `CoreState` 彻底物理隔离；
- [ ] 完成基础播放器组件 `ZakowayPlayer` 及其移动端竖屏与桌面端窗口的基础呈现。

### 阶段二：源调度系统与数据联动 (Source & Business Integration)
- [ ] 将 animaku 的 `use-auto-source-pick`（优先级排序、0ms秒提、1200ms宽限期、自动 Fallback）移植为 Dart 单测可验证的领域逻辑；
- [ ] 与已有的 Bangumi 详情、集数列表完成双向绑定；
- [ ] 历史记录毫秒级存取与续播逻辑（自动对齐最后观看集数与进度）。

### 阶段三：控制条、手势系统与多端布局 (Controls & Gestures)
- [ ] 实现桌面端 / 移动端自适应控制条（包含三等分双击、长按横滑调速、Seek Preview）；
- [ ] 实现桌面端全屏悬浮抽屉 `VideoSidePanel`（在不中断视频的情况下选集与切源）；
- [ ] 实现桌面端全功能键盘快捷键体系与窗口全屏/退出管理。

### 阶段四：自研 Canvas 弹幕与 OP/ED 可视化 (Danmaku & Smart Segments)
- [ ] 实现纯 Flutter Canvas 弹幕渲染引擎（防重叠轨道算法、10s重复去重、休眠省电）；
- [ ] 对接弹弹play弹幕数据源并实现多源合并与过滤规则面板；
- [ ] 实现 `SkipSegmentTrack` 彩色进度条刻度与自动跳过 OP/ED 及其撤销 HUD。

### 阶段五：画质与极致体验增强 (Enhancement & Polish)
- [ ] 打包 Anime4K v4 GLSL 并接入底层 mpv 着色器管道，提供画质分级切换；
- [ ] 实现视频高清截图（纯画面/带弹幕）与保存到本地；
- [ ] 接入外部播放器唤起支持（VLC、PotPlayer、IINA 等）。
